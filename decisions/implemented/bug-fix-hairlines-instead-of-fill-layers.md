# 分块与行边界用 0.5px 发丝线，不靠填充差

## Problem

详情页要把"正文 / 评论 / 文件清单"分成看得出的三块，列表页要让"行与行"分得开。
第一版按常见做法用**填充差**：卡片用 `--dsw-alias-bg-layer-2`、行靠 hover 填充。
挂载门里新加的几何断言当场抓红：卡片的填充与宿主面板底**完全相同**。

## Decision

在流的内部一律用 **0.5px 中性发丝线**做边界（详情卡片 = `border-l2` + 圆角；
列表行间 = `border-l2` 的 `border-top`）。**环境事实**（实测，浅色主题）：
宿主 `bg-base` / `bg-layer-1` / `bg-layer-2` / `bg-layer-3` **全是 `#fff`**，
填充差恒为 0；而官方 `border-l1`（4% 黑）在这个底色上几乎看不见——行线因此取
`border-l2`（10% 黑，实测 `rgba(0,0,0,0.1)`）。分区分界与行边界用**同一档线**，
靠线的数量（行线 + 28px 头带 + 头带底线）区分层级。

## Alternatives considered

- **继续用填充差**：浅色主题下等于没做（第一版就是这个结果）。已证伪。
- **用 `border-l1`**：门打印出 `rgba(0, 0, 0, 0.04)`，肉眼不可辨。已证伪。
- **给行加阴影**：阴影是"抬起"语义，列表行不是抬起面；且阴影在窄条里会互相污染。

## Consequences

- 门里留下了一条**主题无关**的判据："填充与宿主面板底不同 **或** 有非透明发丝边框"，
  且要求卡片数 ≥2、圆角 > 0——第一版正是被它抓出来的。
- 暗色主题下填充差才重新起作用，所以填充仍然保留（作为额外分层，不承担边界职责）。
- 新增自绘分块时照此办理：先问"这条边界在 `#fff` 上看得见吗"。
