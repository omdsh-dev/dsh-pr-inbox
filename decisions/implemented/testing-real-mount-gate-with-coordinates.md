# 验收靠真实挂载门 + 坐标断言，不靠"看起来对了"

## Problem

这是一个浏览器 UI：单测能证明纯函数对，但证明不了"装进真 DSH 之后面板真的渲染、
绑定的是这个项目、行几何真的是我要的那个"。而 agent 与评审者都拿不到稳定的视觉判断
（截图要看、分辨率会变、主题会换）。

## Decision

建**真实挂载门**：build → pack → 装进**隔离 `DSH_HOME` 的全新 profile**（随机的实例、
不碰 `~/.dsh`）→ 用宿主 RPC 种子工作区与会话（cwd = 目标仓库）→ Playwright 打开真 GUI
→ 断言"插件加载 → 原生右栏出现 PR 条目 → 面板渲染出绑定的项目"，并把**几何量成数字**：

- 行几何：头像 / 编号 / 标题 / 时间 / 外链在"简洁"与"详细"两档**逐项同 x 同宽**（容差 1px）；
- 行边界：行间发丝线的宽度与颜色非透明；
- 贴顶：滚动后分区头的 y 等于滚动口上沿（内容不够高时临时压矮滚动口，测完还原）；
- 选中：返回列表后当前项的 2px 强调条（伪元素也要量）。

## Alternatives considered

- **只看截图**：不可重复、不可自信断言，agent 也读不到稳定的像素含义。
- **写死"应该长这样"的像素快照**：字体/主题/平台一变就红，维护成本高于收益。
- **只做 host 路由断言**：证明不了"面板真的渲染"——本次就抓到过一次页签整条崩掉，
  那条路只有浏览器能看见。

## Consequences

- 门是**实例门**（要 gh 登录 + Playwright + 一个仓库路径），不进默认静态门；
  改动 UI 时才跑。
- 几何断言写成"主题无关"的形态（例如边界 = 填充差 **或** 非透明发丝线），
  否则换主题就红。
